# ZigGuard v0.1.0-alpha.1

This is the first public alpha of ZigGuard, a tool-neutral governance layer for AI coding agents.

## Included

- Go CLI with:
  - `zigguard init`
  - `zigguard validate`
  - `zigguard compile`
  - `zigguard check`
- strict ZigGuard policy v0.1 parsing;
- deterministic compilation;
- shared `AGENTS.md` output for Codex, Cursor, and GitHub Copilot;
- `CLAUDE.md` support for Claude Code;
- generated target manifest;
- managed-section merging that preserves pre-existing human instructions;
- safe migration from the legacy fully generated instruction-file format;
- mechanical generated-artifact integrity checks for missing, drifted, or unmanaged governance files;
- JSON check reports for CI;
- official GitHub Action for pull-request governance checks;
- Java + Spring Boot + Oracle reference fixture;
- Linux, macOS, and Windows binaries for amd64 and arm64;
- SHA-256 checksums for release archives.

## Important limitation

This alpha generates **instruction context**.

A policy rule rendered as `BLOCK` or `REQUIRE APPROVAL` is an instruction to the coding agent. It is **not** equivalent to a branch-protection rule, CI gate, operating-system sandbox, security scanner, or other hard enforcement boundary.

`zigguard check` provides the first mechanical enforcement boundary by verifying that required ZigGuard-managed sections/files are present and match the current policy while allowing human-authored content outside managed sections. It still does not enforce the semantic behavior described inside agent instructions.

Additional enforcement is planned through repository/Git policy checks, scanners, and target-specific hooks where technically appropriate.

## Feedback wanted

The main questions for this alpha are:

1. Is `zigguard.yml` understandable and useful?
2. Do the generated instruction files fit real repositories?
3. Which rules should become mechanically enforceable first?
4. Which stacks and agent tools should be prioritized next?

This release should be treated as an early developer preview, not a production security control.
