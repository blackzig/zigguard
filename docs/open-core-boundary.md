# Open-Core Boundary

ZigGuard is intended to support a sustainable open-core business without making the local core artificially incomplete.

## Open-source core

The public core should include:

- policy specification and schema;
- local policy validation;
- deterministic policy compiler;
- supported public adapters;
- local checks;
- public/basic rule packs;
- GitHub Action or equivalent local CI integration where practical.

## Commercial services and products

Commercial offerings may include:

- organization policy synchronization;
- private policy repositories;
- audit history and reporting;
- role-based administration;
- organization-wide dashboards;
- premium/compliance policy packs;
- managed integrations;
- AI-assisted repository analysis;
- hosted collaboration features;
- enterprise support.

## Principle

A developer should be able to use ZigGuard meaningfully without creating an account. Paid products should monetize coordination, scale, proprietary content, compliance, hosting, support, and organization-level governance rather than disabling the core compiler.
